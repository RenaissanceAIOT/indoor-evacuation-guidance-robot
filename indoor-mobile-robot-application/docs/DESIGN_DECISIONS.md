# 设计取舍与技术实现

## 1. 为什么双层控制

实时控制器负责四轮速度闭环、编码器和 IMU 采样；Linux 主控负责 SLAM、导航和视觉。上位机通过矢量速度接口控制底盘，不直接在 Python 中驱动电机 PWM。这样能把模型推理的负载波动与电机控制隔离。

麦轮的轮速分解需要实测轮半径和轴距。轮序、滚子方向和电机符号不能从示意图推定，必须架空逐轮核对。当前协议回传的是 `vx/vy/wz`，无法从中反推四轮原始编码计数。

## 2. 状态估计与 TF 所有权

底盘速度在机体坐标系中，里程计积分为：

```text
x = (vx cos(yaw) - vy sin(yaw)) dt
y = (vx sin(yaw) + vy cos(yaw)) dt
yaw = wz dt
```

底盘节点发布原始 `/odom` 和六轴 IMU；EKF 发布连续 `odom→base_link`，AMCL 或 SLAM 发布全局 `map→odom`。同时启用 EKF 时关闭底盘 TF，防止两个节点争用同一变换。IMU 没有绝对航向，不能声称消除了长期漂移。

## 3. 出口评分与路径规划的区别

实时任务节点先排除禁用/封锁出口，然后计算：

```text
J(exit) = wd × EuclideanDistance(robot, exit)
        + wh × configured_hazard_risk
        + wc × configured_crowd_density
```

权重是决策偏好，不是经实验校准的概率模型。风险和拥堵目前来自静态参数，封锁来自话题。评分决定“去哪一个出口”；Nav2 决定“怎样走”。欧氏距离不保证地图可达，因此导航失败后切换候选出口，并保留失败样本。

独立 `RiskGraph` 采用非负边代价的 Dijkstra，可评价多走廊风险路径；`replay_scenario.py` 用虚构数据检验它。目前未将此图路径强制传给 Nav2，不能称为在线风险 costmap。

## 4. 异步任务所有权

Action 取消响应只表示请求处理，并不意味着旧目标已终止。`GoalLifecycle` 为每次目标生成递增 token：

1. 持有目标期间禁止第二次 begin；
2. 出口封锁记录 reselect 意图；警情解除/故障取消优先；
3. 如果取消发生在接受响应前，目标一旦被接受立即取消；
4. 等待旧目标终态后才发送新目标；
5. 旧 token 回调不能修改当前目标；主动取消不被判作出口失败。

这样避免导航失败重试和主动切换两个流程同时下发目标。ROS Action 传输异常与取消失败仍需整机故障注入验证；任务没有确认终止时不启动新目标。

## 5. RGB-D 三维定位

RGB 与已对齐深度近似时间同步。目标框中心取 7×7 深度窗口，过滤无效值后用中值估计距离：

```text
Z = median(valid_depth) × depth_scale
X = (u - cx) × Z / fx
Y = (v - cy) × Z / fy
```

`16UC1` 使用配置的深度比例，`32FC1` 按米处理。拒绝无效内参和尺寸不一致图像。输出位于相机 optical frame，要进入地图决策必须经过 TF 变换。中心深度可能落在背景，未实现实例掩膜、跨帧跟踪或自动人群密度估计。

## 6. 软件降级而非消防安全承诺

| 条件 | 软件处理 | 仍需验证 |
| --- | --- | --- |
| 速度指令超过 350 ms | 按 20 Hz 重发零速 | 制动距离与 MCU 响应 |
| 遥测超过 300 ms / 未收到遥测 | 拒绝非零速度 | 物理链路中断时 MCU 自主停车 |
| 雷达过期 / 电源不足 / diagnostics 错误 | supervisor 发出运动禁止，取消导航 | 故障检测与制动总时延 |
| 曾接收联锁后超过 1.5 s 无更新 | 底盘禁止速度执行 | 节点退出/网络分区测试 |
| 机械臂未验证 | `arm_enabled=false` | 固件格式、零位、载荷与碰撞 |

基础 hardware 模式允许架空遥控测试，不自动要求 supervisor；导航模式启动 supervisor。停止监督节点后联锁不会静默失效，恢复操作应检查设备并重新启动相关节点。上述联锁为研究级软件措施，不能替代物理急停。
