## 已知限制

1. URDF 使用名义外廓，必须替换为实际测量值；
2. 上位机接收的是底盘矢量速度，不是四个轮子的原始编码器计数；
3. 六轴 IMU 没有绝对航向，长期漂移依赖激光定位修正；
4. 电量百分比为电压线性估计，负载变化时存在偏差；
5. YOLO 权重不随仓库分发，部署时要固定版本和哈希；
6. 出口风险与拥堵由配置或外部话题提供，尚未接入建筑信息系统；
7. Nav2 参数必须根据地面摩擦、走廊宽度、雷达视场与实际外廓调节；
8. 机械臂控制必须先抓包核对固件帧格式，再进行低角度空载测试；
9. 健康监控接入任务取消和底盘速度联锁，但不替代实时控制器独立看门狗或硬件安全逻辑；
10. 感知结果没有自动更新风险/拥堵或驱动机械臂抓取，视觉跟踪与人体姿态模型是后续研究项；
11. 离线图路由未接入实时任务，实时任务采用欧氏距离与配置风险评分；
12. motion mock 没有碰撞模型、激光或 Nav2 场景，不能作为导航仿真验收；
13. 机械臂桥只发送最后一个轨迹点的位置，不执行时间轨迹、不做 IK 或碰撞检查，默认禁用；
14. 本地尚未运行 ROS 2 / colcon / Nav2 / 相机模型，语法和纯逻辑测试不等于整机联调通过。

## 下一阶段研究

- 设计面向烟雾/拥堵风险的 Nav2 costmap layer；
- 研究基于人员流向和局部密度的动态出口代价；
- 建立 rosbag 回放和导航参数回归测试；
- 加入串口自动重连、生命周期管理和硬件停止输入；
- 完成 Raspberry Pi 5 长时间温度、CPU、内存和推理延迟测试；
- 研究灯光、语音、姿态组合对人员跟随意愿的影响；
- 进入真实楼宇试点前完成消防、隐私、网络安全和功能安全评审。
