## 90 秒讲述

这个项目来自亚洲大学与 KITECH 产学研合作背景。实验室已经积累了自主导航和智能疏散方面的研究，我的工作是继续向应用层推进：把移动底盘、激光雷达、RGB-D 相机和机械臂接入 ROS 2，形成可实际运行的楼宇机器人系统。

公开工程版中，底层由 STM32 承担编码器采样、电机 PID 和麦轮运动学，上位机提供协议驱动、速度门控和状态反馈。导航采用全向 AMCL/DWB 与 EKF，视觉把 YOLO 二维框和深度图融合为三维目标位置。底层固件不包含在本仓库，具体历史分工以实际记录为准。

应用层不是简单发送导航点，而是维护任务状态：事件触发后根据距离、风险和拥堵选择出口；出口失效时取消当前目标并重选；底盘、雷达或电源异常时系统进入不可用状态并停止任务。同时记录 JSONL 事件日志，方便复盘。项目的重点是把多个研究模块变成可诊断、可降级、可测试的完整机器人系统。

## 高频追问

### 为什么使用 Raspberry Pi + STM32 双层结构？

Linux 适合运行导航、视觉和任务管理，但调度延迟会随负载变化。编码器采样、电机 PID 和运动学留在 STM32，实时域和算法域职责清晰。

### 麦克纳姆轮对导航有什么影响？

控制器必须支持正负横向速度；侧向滑移会放大里程计误差，因此限制加速度，并依靠 IMU/EKF 与激光定位进行修正。

### 如何处理通信中断？

上位机驱动具有 350 ms 速度命令看门狗、遥测超时诊断和错误帧重同步；实际系统还需要实时控制器独立看门狗与物理停止装置。

### 这个系统能直接用于真实火灾吗？

不能。当前成果验证楼宇导航和人员引导链路。真实部署需要经过耐环境、功能安全、消防法规、隐私和可靠性评审，并接入经过确认的建筑事件系统。

## 量化结果写法

只有测试记录包含日期、场地、样本数、commit 和原始日志后，才能写：

> 在 N 次楼层导航测试中达到 X% 任务成功率，终点误差中位数 Y m；在 N 次动态横穿测试中保持 0 碰撞，规划恢复率 Z%。

不要把测试目标、仿真结果或剪辑视频写成统计结论。
