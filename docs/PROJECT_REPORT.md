# 项目书：基于 ROS 2 的室内移动机器人应用原型

## 1. 项目定位

本项目以实验室既有自主导航、人机交互与智能疏散研究为基础，继续研究这些成果如何转化为楼宇中的可运行应用。系统面向走廊、门厅和实验室等半结构化环境，完成自主移动、环境感知、目标识别、出口选择、引导执行与运行监控。亚洲大学 CAD/CAM 研究室与 KITECH 的产学研合作课题提供应用研究背景；仓库聚焦个人负责的系统工程工作。

研究经历周期：2025.11—2026.02；公开工程整理版：2026.10。

以下描述当前公开代码与应用方案，不把本次补充代码、配置或工作分解追溯为当年逐项完成的历史记录。疏散引导是系统能力的扩展场景，主线仍是室内机器人集成。

角色：项目研究员（KITECH 产学合作场景下的机器人原型研发）。

## 2. 问题定义

### 2.1 用户问题

在烟雾、拥堵、局部通道阻塞或陌生建筑中，人员无法只依赖静态指示牌判断哪条路线仍然可行。移动机器人可以把最新路径计算结果带到人员附近，但前提是其导航链路在传感器噪声、行人动态障碍和底盘通信异常下仍可控。

### 2.2 工程目标

1. 建立 Raspberry Pi 5 与 STM32 的分层控制结构，使实时电机环和高层算法解耦。
2. 打通 `/cmd_vel → 串口协议 → 底盘运动 → 编码器/IMU → /odom` 闭环。
3. 以激光雷达完成二维建图、AMCL 定位、全局规划和局部动态避障。
4. 以 RGB-D 相机完成目标检测与距离估计，并预留颜色、巡线、手势交互接口。
5. 以状态机组织“待机—警情—出口选择—导航引导—到达/重规划—故障”过程。
6. 给出能够复现、测试和继续标定的代码、参数与记录模板。
7. 记录系统健康与任务事件，使场景实验能够复盘。

### 2.3 非目标

- 不把视觉模型输出当作认证火警信号；
- 不在真实火场运行普通消费级底盘与相机；
- 不承诺未经现场测试的成功率、定位误差或续航；
- 不发布或改编设备技术资料、固件和图片资源。

## 3. 系统方案

### 3.1 控制分层

| 控制域 | 周期/触发 | 实现 | 原因 |
| --- | --- | --- | --- |
| 电机、编码器、麦轮运动学 | STM32 实时任务 | STM32F407 控制板 | 避免 Linux 调度抖动进入电机闭环 |
| 底盘设备桥 | 100 Hz 轮询，50 Hz 遥测 | `escape_robot_base` | 管理串口、协议、看门狗与 ROS 消息 |
| 状态估计 | 30 Hz | robot_localization EKF | 融合轮速里程计与 IMU 角速度 |
| 建图/定位 | 激光帧驱动 | SLAM Toolbox / AMCL | 生成并复用二维占据栅格地图 |
| 规划控制 | 5 Hz / 15 Hz | Nav2 SmacPlanner2D + DWB | 支持全向底盘和动态代价地图 |
| 视觉 | 配置上限 10 Hz | YOLO + RGB-D | 用限频控制负载，实际速度需测量 |
| 任务编排 | 事件驱动 | 疏散状态机 | 明确故障转移和出口重选逻辑 |

### 3.2 关键动作与实现

#### 动作 A：建立 ROS 2 与 STM32 数据闭环

- 根据实验平台接口定义实现双帧头、长度、功能码、大端 int16 和累加校验规则；
- 将 `Twist.linear.x/y` 与 `angular.z` 放大 1000 后封装为 0x50 帧；
- 增量解析 0x10 遥测帧，完成加速度、角速度、底盘速度和电池电压的单位换算；
- 对半帧、粘包、噪声和错误校验进行重同步；
- 增加 350 ms 速度看门狗、300 ms 遥测门控及运动联锁，异常时按 20 Hz 重发零速；断线后的实际停车必须由 MCU 看门狗保证。

#### 动作 B：让全向底盘进入 Nav2

- 建立 `map → odom → base_link → sensor` TF 树；
- 底盘节点发布轮速里程计，EKF 融合 MPU6050 角速度并发布 `odom → base_link`；
- AMCL 使用 `OmniMotionModel`，DWB 打开正负 `vy` 采样；
- 使用矩形 footprint 而非圆形半径，避免机械臂底座和麦轮外缘被低估；
- 将速度、加速度和膨胀半径设置为保守初值，再通过走廊实测逐项收敛。

#### 动作 C：融合视觉与深度

- 用近似时间同步器配对 RGB 与对齐深度帧；
- YOLO 输出二维框后，在框中心小窗口取有效深度中值，降低空洞与离群点影响；
- 通过相机内参把像素中心反投影为相机坐标系三维点；
- 发布结构化 JSON、`PoseArray` 与调试图，供跟踪、行为和可视化使用；
- 颜色、巡线和手势节点作为低速实验功能，与安全导航链路隔离。

#### 动作 D：构建疏散任务状态机

- 外部报警网关发布 `/hazard/active`；
- 出口评分综合当前位置距离、出口风险和人群密度，屏蔽已封锁出口；
- 通过 `NavigateToPose` 下发目标，目标失败时把当前出口加入阻塞集合并重选；
- 同步触发 RGB 灯与蜂鸣器；解除警情时取消目标并回到待机状态；
- 新目标等待旧目标终态；主动取消不计为出口导航失败；
- 若 Nav2 不可用或没有可用出口，进入 `FAULT/BLOCKED`，不继续盲目移动。

#### 动作 E：建立系统健康与实验记录

- 监控底盘 diagnostics、激光扫描时间戳和电池电压；
- 只有关键设备数据新鲜且电压满足阈值时发布 `/system/ready=true`；
- 将任务状态按 UTC 时间写入 JSONL，便于对照 rosbag 分析；
- 将 readiness 接入任务取消，`/base/stop` 接入底盘速度门控；监督节点心跳丢失同样禁止运动；
- 把故障停车、导航失败和出口切换纳入同一验收矩阵。

## 4. ROS 接口

| 类型 | 名称 | 方向 | 说明 |
| --- | --- | --- | --- |
| `geometry_msgs/Twist` | `/cmd_vel` | 订阅 | 底盘目标速度 |
| `nav_msgs/Odometry` | `/odom` | 发布 | STM32 反馈速度积分的原始里程计 |
| `sensor_msgs/Imu` | `/imu/data_raw` | 发布 | 加速度与角速度；无绝对姿态 |
| `sensor_msgs/BatteryState` | `/battery_state` | 发布 | 电压、估算百分比与健康状态 |
| `trajectory_msgs/JointTrajectory` | `/arm_controller/joint_trajectory` | 订阅 | 6 关节位置指令 |
| `geometry_msgs/PoseArray` | `/perception/detections_3d` | 发布 | RGB-D 目标三维位置 |
| `std_msgs/Bool` | `/hazard/active` | 订阅 | 经验证的外部警情开关 |
| `std_msgs/String` | `/hazard/blocked_exits` | 订阅 | 逗号分隔的封锁出口 ID |
| `std_msgs/String` | `/guidance/status` | 发布 | 状态机 JSON 快照 |
| `std_msgs/Bool` | `/system/ready` | 发布 | 设备与能源是否满足任务条件 |
| `std_msgs/String` | `/system/health` | 发布 | 系统健康 JSON 快照 |

## 6. 风险与控制

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 麦轮在不平整地面打滑 | 里程计漂移、定位波动 | IMU/EKF、激光定位、限制加速度、实测协方差 |
| 树莓派视觉负载过高 | 控制延迟 | 限制推理帧率、使用轻量模型、导航与视觉进程隔离 |
| 串口帧丢失或粘包 | 状态更新中断 | 增量解析、校验和、遥测超时诊断、速度看门狗 |
| 机械臂改变质心/外廓 | 碰撞风险 | 行驶姿态固定、更新 footprint、限制速度 |
| 视觉误检火情 | 错误任务触发 | 只接受外部验证报警；视觉仅作辅助感知 |
| 出口全部不可用 | 无有效路径 | 停车、声光告警、发布 `BLOCKED` 请求人工接管 |

## 7. 交付判定

仓库中的数字阈值是**验收目标或配置初值**，不是尚未提供 rosbag/记录时的实验结论。只有在 [TEST_PLAN.md](TEST_PLAN.md) 的记录表中填入日期、场地、样本数和日志链接后，才可把目标改写为简历中的量化成果。
